Chi sono

Sono uno sviluppatore software in BARS a Roma, partner DocuSign. Il mio lavoro quotidiano è integrare DocuSign con i sistemi enterprise (SAP, SharePoint, Microsoft Entra ID e piattaforme HR) usando Java/Spring Boot, Node.js e TypeScript: API backend, integrazioni OAuth 2.0 e SOAP/REST, contratti dati XML/JSON e i frontend che li accompagnano.

Cliente enterprise · in corso

Dati documentali SAP per DocuSign Maestro

Esigenza
Prima della firma, un workflow Maestro deve recuperare da SAP i dati del documento corretto, ma gli utenti conoscono solo un numero di richiesta interno (RDA).
Il mio ruolo
Ho sviluppato una DocuSign Data IO Extension App privata in Node.js/Express che Maestro chiama server-to-server. Interroga SAP via SOAP e restituisce al workflow ID, titolo e stato del documento.
Flusso
Maestro web form→, then Data IO extension (OAuth 2.0)→, then SAP (SOAP)→, then document data→, then signature step
Scelta chiave
Le OAuth 2.0 client credentials rendono l’estensione un servizio server-to-server puro, senza login utente; un tunnel ha reso testabile l’intero giro con SAP durante lo sviluppo.
Stato
Prototipo funzionante · in corso

  • Data IO Extension
  • Node.js
  • Express
  • OAuth 2.0
  • SOAP
  • SAP

Cliente enterprise · proof of concept

Ordini d’acquisto da SharePoint → DocuSign

Esigenza
I fornitori devono firmare l’ordine d’acquisto insieme a tutti i documenti di supporto salvati in SharePoint, inviati in un’unica busta.
Il mio ruolo
Ho sviluppato un servizio Java/Spring Boot: da numero e revisione dell’ordine trova la cartella SharePoint via Microsoft Graph, raccoglie i PDF, compone la busta DocuSign (ordine principale per primo) e la invia, restituendo ID, stato e avvisi.
Flusso
PO request (REST)→, then Spring Boot→, then Microsoft Graph / SharePoint→, then envelope assembly→, then DocuSign→, then vendor
Scelta chiave
Una modalità mock esegue l’intero flusso senza credenziali Microsoft o DocuSign, e il contratto REST è pensato per essere chiamato da SAP: si può dimostrare e testare prima di avere accesso ai sistemi del cliente.
Stato
Proof of concept
  • Java
  • Spring Boot
  • Microsoft Graph
  • SharePoint
  • DocuSign eSignature API
  • REST
  • Docker
Versione di test pubblica (modalità mock) → github.com/Tridrik-Dey/sharepoint-docusign-poc

Cliente enterprise · proof of concept

Dati dei firmatari da Microsoft Entra ID

Esigenza
I documenti firmati devono riportare gli attributi aziendali e HR di mittente e dipendente, pronti per l’archiviazione in un sistema documentale.
Il mio ruolo
Ho sviluppato un servizio TypeScript che risolve i ruoli della busta, trova gli utenti per email in Microsoft Entra ID via Microsoft Graph e scrive gli attributi mappati come campi personalizzati.
Flusso
DocuSign envelope→, then roles→, then email→, then Microsoft Graph /users→, then mapped attributes→, then envelope custom fields
Scelta chiave
Quali ruoli e attributi usare è definito in un file di mappatura, così si può cambiare senza modificare il codice.
Stato
Proof of concept
  • TypeScript
  • Node.js
  • Microsoft Graph
  • Entra ID
  • DocuSign eSignature API
  • Vitest

Cliente enterprise italiano · in corso

Firma elettronica HR e archiviazione in Zucchetti

Esigenza
I documenti di onboarding HR devono essere firmati in presenza su tablet e poi archiviati automaticamente nella cartella del dipendente in Zucchetti HR.
Il mio ruolo
Ho scritto l’analisi funzionale bilingue (EN/IT) e sviluppato il prototipo di fase 1: firma in presenza, archiviazione e registro delle azioni, su dati mock.
Flusso
HR on tablet→, then in-person signature→, then signed documents→, then Zucchetti HR (employee folder)→, then action log
Scelta chiave
DocuSign e Zucchetti sono dietro adapter: le integrazioni reali sostituiscono i mock senza cambiare interfaccia o regole di business.
Stato
Analisi + prototipo di fase 1 · in corso

  • Zucchetti HR
  • Node.js
  • Adapters
